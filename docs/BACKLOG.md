# StudyFlow Product Backlog

This backlog contains the initial prioritized user stories for StudyFlow.

Definition of Done: see [`README.md`](../README.md).

| ID | User Story | Priority | Initial Estimate | Status |
|---|---|---|---:|---|
| US-01 | As a new user, I want to create an account so that I can securely access my academic information. | High | 3 | Backlog |
| US-02 | As a registered user, I want to log in and log out securely so that my academic data remains private. | High | 5 | Backlog |
| US-03 | As a student, I want to create and manage courses so that I can organize tasks by course. | High | 3 | Backlog |
| US-04 | As a student, I want to create academic tasks so that I can track assignments, exams, and projects. | High | 5 | Backlog |
| US-05 | As a student, I want to edit and delete tasks so that my academic information remains accurate. | High | 3 | Backlog |
| US-06 | As a student, I want to view my active tasks on a dashboard so that I can quickly understand my workload. | High | 5 | Backlog |
| US-07 | As a student, I want to record task progress so that I know how much work remains. | High | 3 | Backlog |
| US-08 | As a student, I want StudyFlow to assign Task Attention Levels to my active tasks so that I can decide what to work on first. | Medium | 5 | Backlog |
| US-09 | As a student, I want to search and filter tasks so that I can quickly find relevant academic work. | Medium | 3 | Backlog |
| US-10 | As a student, I want to view workload information so that I can better plan upcoming study time. | Medium | 5 | Backlog |
| US-11 | As a student, I want a calendar or timeline view so that I can understand upcoming deadlines visually. | Low | 5 | Backlog |
| US-12 | As a student, I want StudyFlow to suggest how to break down a large task so that I can plan complex assignments. | Low | 8 | Backlog |

## Priority Level Key

- **High:** Required for the core MVP and should be implemented first.
- **Medium:** Important features planned after the core MVP is stable; they may be added in a later milestone if time allows.
- **Low:** Optional enhancements considered after High- and Medium-priority work is complete.

## Status Definitions

- **Backlog:** Not yet started.
- **In Progress:** Currently being implemented.
- **In Review:** Implementation is complete and awaiting review or verification.
- **Done:** Meets the project's Definition of Done and has been integrated into the appropriate shared branch.
